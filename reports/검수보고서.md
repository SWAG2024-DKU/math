## 1. 배포 전에 반드시 수정할 수학·조건 오류

### 1-1. 미적분 2: 요구 차수와 정답 차수가 다름 — 63개

해당 유형:

- `power_series_substitution`: 21개
- `bessel_series_derivation`: 21개
- `power_series_solution_construction`: 21개

문장에 `x^(2{{ N }})`가 들어 있어 N=3이면 `x^(23)`으로 출력됩니다. 정답 계산은 2×N=6으로 하고 있습니다. 따라서 문제는 23차까지 요구하는데 답은 6차까지만 나옵니다. N=1,2,3 모두 동일한 종류의 오류입니다.

실제 예:

`calculus_2/all_20261005T044638Z_515a1d1e/power_series_substitution/start_17_actual_17.json`

문제: `1/(1-9x²)`의 급수를 `x^(22)` 항까지 쓰시오.

저장 답: `1 + 9*x**2 + 81*x**4`.

문장의 요구대로라면 0≤j≤11에서 `Σ 9^j x^(2j)`까지 필요합니다. 의도한 문제 차수가 4차였다면 문장을 `x^({{ 2*N }})`로 고치고 재생성해야 합니다. 기존 답을 무작정 22차로 늘리는 것보다는 원래 의도대로 차수를 바로잡는 편이 사람에게도 적절합니다.

수정 위치: `scripts/problems/calculus_2_rule_profiles.py`의 세 문장 → Rule 재적용 → 해당 Template 및 Preview 재생성. 개별 Instance 63개를 손으로 고치지 마세요.

### 1-2. 확률통계: 소수 표시로 인한 정확값 불일치 — 6개(기각 반전 1개 포함)

파일:

`probability_statistics/all_20261011T141047Z_ce88d904/hypothesis_decision/start_20_actual_20.json`

문제: μ0=6, σ=2, n=9, 표본평균=7.333333333333333. 규칙은 |Z|≥2.

저장 답: `true`.

문장에 적힌 소수를 정확한 숫자로 읽으면:

`Z=(7.333333333333333-6)/(2/3)=1.9999999999999995 < 2`.

그러므로 원문 숫자에 대한 판정은 `false`입니다. 내부에서 의도한 평균 22/3을 문장에도 정확하게 표시해야 `true`가 맞습니다.

같은 방식으로 긴 소수가 출력된 검정/통계량/검정력 Instance는 9개입니다. 그중 기각 판정이 실제로 뒤집힌 것은 위 1개입니다. 다른 5개(검정통계량 3개, 검정력 2개)는 문장 숫자를 정확히 읽을 때 저장된 정확값과 미세하게 다릅니다. 이 5개도 엄격한 정확값 검수에서는 실패로 셌습니다. 나머지 3개는 표시가 길어도 저장된 최종 판정/값은 일치합니다. 이 정밀도 문제 5개를 급수 누락이나 기각 판정 반전과 같은 크기의 수학적 오류로 보지는 않습니다. 예를 들어 같은 seed의 `test_statistic_calculation`은 원문 Z가 2보다 조금 작지만 정답은 정확한 2입니다.

수정 위치: `scripts/problems/probability_statistics_rule_profiles.py`의 숫자 표시 계약, 필요시 `problem_instance_generator.py`의 **확률통계 표시 경로만**. Jinja 식 안의 나눗셈 결과를 그대로 출력하지 말고 정확한 분수로 미리 계산해 문자열 또는 LaTeX로 전달하세요. 판정식 `≥2`를 임의로 바꾸거나 허용오차로 오류를 덮으면 안 됩니다.

## 2. 기호·문장·답 형식 확인사항

건수는 파일 수이며, 다른 항목과 겹칠 수 있습니다.

| 항목 | 유형 | 전체 건수 | 확인·수정 내용 |
|---|---|---:|---|
| 닫는 괄호 누락 | 공학수학 `superposition_verification` | 11 | `cos(2t의`처럼 출력됨. `cos(2t)의`로 수정 |
| 미정의 n | 공학수학 `complex_fourier_calculation`, `fourier_series_calculation` | 22 | 주파수는 숫자로 바뀌었는데 요구 답은 c_n, (a_n,b_n). n의 값을 명시하거나 계수 첨자를 실제 숫자로 출력 |
| 미정의 a | 공학수학 `generalized_eigenvector_solving` | 11 | M-aI의 a가 정의되지 않음. `a=17` 또는 `M-17I`처럼 명시 |

| 행·열 번호의 시작값 불명확 | 선형대수 `ero_application`, `elementary_matrix_construction`, `free_variable_identification` | 60 | 내부는 0부터 시작. 문장에 이를 명시하지 않아 일반적인 1부터 번호와 충돌 |
| 요구 답 형식 불충족 | 미적분 1 `partial_fraction_decomposition` | 21 | 동치값은 맞지만 답이 원래 곱분모 식으로 합쳐져 있음. 부분분수 형태를 보존 |
| 정의역 메타데이터 불일치 | 미적분 1 접선/선형화 4종 | 84 | domain=[1,3]인데 기준점=0. domain이 함수 정의역인지 샘플링 메타데이터인지 정리 |
| 부호 표현 | 여러 유형 | 231 | `x--4`, `x=4+-1` 등. 괄호 또는 계산된 부호로 출력 |
| CAS/Python 표기 | 여러 유형 | 1,773 | `Matrix(...)`, `**`, `Abs` 등. 서비스 화면에서는 수학식으로 렌더링 권장 |

특히 행 번호 사례: `R_2+(-1)R_1→R_2`인데 저장 E는 세 번째 행·두 번째 열을 바꿉니다. 0부터 번호라는 전제에서는 맞지만, 보통 교재의 1부터 번호로 읽으면 다른 답입니다. 명시적 번호 기준이 필요합니다. 이번에는 선형대수 파일을 변경하지 않았습니다.

부분분수 예: 1/[x(x+6)]의 분해 답은 `(1/6)/x-(1/6)/(x+6)`이어야 합니다. 현재 저장된 `1/(x*(x+6))`는 값의 동치 검사에는 통과해도 분해 결과 제시라는 요구를 만족하지 않습니다. `apart` 결과를 일반 `simplify`로 다시 합치는지 확인하고 해당 유형의 답 표현을 보존하세요.

정의역 메타데이터는 문장에는 나타나지 않아 다항함수의 수치 접선 답 자체를 틀렸다고 판정하지 않았습니다. 다만 domain이 실제 함수 정의역이면 x=0에서 접선을 요구할 수 없으므로 의미를 확정해야 합니다.

## 3. 추가로 검사한 필수 사항

- 외부 ZIP CRC 검사: 손상 파일 없음.
- 모든 JSON 읽기 및 Instance–Template 식별자·과목·유형 비교: 불일치 없음.
- 정수 파라미터의 선언 타입·범위·제외값·choices: 위반 없음.
- Template 문장과 저장 파라미터의 렌더 결과: 불일치 없음. **Template 문장 자체의 차수·기호 오류는 별도 검사로 발견했습니다.**
- 동일 Template ID·동일 문장에 서로 다른 저장 정답: 발견되지 않음.
- 배치 내 유형 수준의 문장 중복: 미적분 1의 `domain_range_identification`, 미적분 2의 `work_calculation`. 두 Concept별 Template이 동일 문제를 만들어 유형 폴더 내에서 겹칩니다. 84개 파일이 해당 그룹에 속하며, 이는 84개의 중복 쌍이라는 뜻이 아닙니다. Template ID별로만 중복 검사하면 놓칠 수 있습니다.
- 검사 가능한 정확분수에서 기약분수의 분자·분모가 두 자리를 넘는 사례는 발견하지 못했습니다. 표현 전체의 난이도·계산 시간은 분수 크기와 별도로 봐야 합니다.

- `reviewed`/`ready`라는 상태 문자열만으로 실제 사람 검수 완료를 입증하지는 않았습니다. 이번 보고서의 자동 검사 통과만으로 상태를 일괄 승격하지 마세요.

## 범위의 한계

이 검수는 저장된 10,386개와 그 고정 문장 계약에 대한 검사입니다. 새로운 함수족, 다른 문장, 모든 가능한 seed를 검증한 것은 아닙니다. 고정 계약은 모두 검산했지만 자유로운 한국어 문장의 완전한 의미 판정이나 증명의 완전성을 수학 정리 증명기처럼 보장하지 않습니다. 자동 계산이 맞더라도 위 문장/가정 문제는 남습니다.

확률통계는 23개 대표 Rule 유형의 23개 Template입니다. 이 파일들에 모든 유형 이름이 있다는 사실이 확률통계 전체 Concept·공식을 모두 다루었다는 뜻은 아닙니다. 학습 범위와 난이도 균형은 별도 콘텐츠 검토가 필요합니다.

원본 ZIP에는 현재 생성기/Rule profile 코드 전체가 들어 있지 않으므로 코드의 발생 원인과 수정 위치는 Template snapshot과 앞서 사용한 프로젝트 구조를 근거로 제시했습니다. 실제 최신 코드를 덮어쓰는 패치는 이 보고서에 포함하지 않았습니다.
