# 선형대수 다양성 확장 — 함수별 TODO 작업 묶음

이 ZIP은 완성 패치가 아니라 구현 작업용 소스와 함수별 TODO입니다.
기존 파일 12개는 함수 구현을 그대로 유지하고 한국어 TODO 주석만 추가했습니다.
신규 파일 3개는 미구현 뼈대이며 실행하면 NotImplementedError가 발생합니다.
실제 E: 프로젝트와 원본 JSON은 변경하지 않았습니다. 운영 프로젝트에 통째로 덮어쓰기 전 작업용 복사본에서 구현하세요.

## 목적

- JSON을 손으로 편집하지 않고 Python 정책이 유형별 분수·계수·행렬 구조를 정의하게 합니다.
- 기존 규칙/템플릿의 승인·검수 정보와 사용자 제약은 원본 스냅샷 및 이력으로 보존합니다.
- 확장된 생성 범위는 새 검증 대상입니다. 기존 승인 사실을 새 범위의 검수 완료로 자동 취급하지 않습니다.
- 레거시 생성 결과를 기본값으로 유지하고 선형대수 확장 정책은 opt-in으로 연결합니다.
- 미적분학 1·2, 공학수학, 확률통계의 기본 샘플링을 바꾸지 않습니다.

## 현재 코드에서 확인한 원인

실행 가능한 선형대수 템플릿은 현재 62개이고 모두 문장 템플릿이 하나입니다.
입력 파라미터는 주로 matrix/vector/integer이며 원소 타입은 기본 integer입니다.
sample_scalar의 유리수 기본 방식은 고정 분모 10 격자입니다.
특수 생성기는 작은 후보·대각/반대각·고정 직교 방향 등의 제한이 있습니다.
_answer_fraction_grade는 분자/분모 최대 99와 무리수·복소수 제한을 적용합니다.
activate_advanced_linear_algebra.upgrade는 현재 parameter_spec/constraints/검수 플래그 등을 다시 지정합니다.
이 제한을 확인하지 않고 숫자 범위만 넓히면 탈락률·연산량만 증가할 수 있습니다.

6. 독립 검증 및 유형별 다양성 지표를 측정하고 원본 검수정보 보존·다른 과목 무변경을 확인합니다.

기존 build_problem_templates.py는 전역 registry를 사용하므로 후보 디렉터리만 만들었다고 자동으로 후보 규칙을 읽지 않습니다.
이 경로 연결 자체가 TODO입니다. 새 CLI는 미구현이므로 지금 실행할 수 있는 완료 명령으로 취급하지 마세요.

## 이번 범위

우선 문장 의미·묻는 대상은 유지하고 계수/입력 구조를 다양화합니다.
단순 문구 변형이나 새로운 문제 의미를 추가할 때는 별도 독립 문장 계약이 필요합니다.
정수 전용 유형에 분수를 강제로 넣지 말고 유형별 허용성을 명시합니다.
기존 independent_statement_contracts.json은 읽기 참조이며 이 묶음에 수정본을 넣지 않았습니다.
다항식 계수도 실제로 명시적 polynomial 입력인지 행렬의 특성다항식/계수 표현인지 구분합니다.

## 완료 기준

- 같은 정책·seed·버전으로 재현 가능하고 반복 재생성 결과가 의미상 같습니다.
- 기준점의 기존 검수정보/수학 계약/사용자 변경사항을 보존하고 변경 차이를 설명할 수 있습니다.
- 지원 대상 6단원 전 유형에서 생성이 이뤄집니다. 제외/부분 실패/0건 유형을 숨기지 않습니다.
- 독립 검증 failed/unsupported/timeout이 0이며 변조된 문제는 거부합니다.
- 분수·계수·행렬 구조 분포와 exact 중복률이 정책별 사전 정의한 기준을 충족합니다.
- 생성 탈락률과 정답 난도 필터 통과 후 분포도 함께 보고합니다.
- 유한 표본 검증을 모든 가능한 문제에 대한 증명으로 표현하지 않습니다.
